YEOFR for Capacitor

This guide is for plugin 0.5.0 (iOS engine 0.11.2, Android engine 0.2.29).

On-device face recognition with liveness for Capacitor apps on iOS and Android, from one TypeScript API.

This guide takes an Ionic Angular app from install to a working face screen: install, the transparent page, a small Angular service, what each status means, enrolment, licensing, hardened builds and troubleshooting. The plugin itself has no Angular dependency; the Angular code here is one way to use it.

Recognition needs a real phone. The app builds and runs in the iOS simulator and the Android emulator, but neither gives the engine a real face, so results stay at noFace. That is expected, not a fault.

What you get

Piece Version Where it comes from
Capacitor plugin @yeomessagingcom/capacitor-yeofr 0.5.0 npm
iOS engine YEOFR 0.11.2 Swift Package Manager, from YEOFR-SPM, resolved for you
Android engine com.yeomessaging:yeofr-android 0.2.29 Maven, from the private YEO repository, with credentials YEO gives you

The plugin pins both engine versions. getVersion() returns the engine version (0.11.2 on iOS, 0.2.29 on Android), not the plugin version.

How it works:

  • The native layer owns the camera. It draws the preview in a native view behind the WebView.
  • Your page is transparent where the camera should show, and draws its own overlay: prompts, buttons, progress.
  • Only small JSON events reach JavaScript. Frames never do.
Event When
result Every analysed frame while the camera runs: the trust status for the face in view.
enrolProgress Every analysed frame while an enrolment capture is running.
registered An enrolment capture finished and the face is stored.
error Something failed after start() resolved.

Frameworks. The plugin is framework-agnostic: any web framework running in a Capacitor shell uses the same TypeScript API, whether Angular, React, Vue, Svelte or plain JavaScript, with or without Ionic. The examples are Angular because the first client is; React Native and Flutter apps keep using their own bridges.

Shells. This release supports Capacitor apps. The native layer is built independently of the shell, so Cordova apps, and native iOS or Android apps that host your web app in their own web view, are supported by the same design and delivered on request. The Angular code in this guide does not change for them; only the small transport class does.

Limits of this release:

  • One camera session per app at a time.
  • Continuous status only. There is no one-shot check call yet.
  • Portrait only. The preview does not follow device rotation, so lock the face page (or the app) to portrait.
  • No browser build. In a browser every engine call rejects with UNAVAILABLE and getVersion() resolves 'web', so your web build and unit tests still run.

Install

npm install @yeomessagingcom/capacitor-yeofr
npx cap sync

iOS

The plugin is a Swift package. Swift Package Manager is the recommended way to consume it on both Capacitor 7 and 8. A podspec is included for Capacitor 7 projects that still build with CocoaPods; see "Capacitor 7 on CocoaPods" below.

  • New iOS project: npx cap add ios --packagemanager SPM.
  • Existing project on CocoaPods: migrate it with npx cap spm-migration-assistant, or stay on CocoaPods and follow the Capacitor 7 steps below.

Then:

  1. Set the iOS deployment target of the App target to 17.0 in Xcode, then run npx cap sync again. The Capacitor CLI reads the deployment target from the Xcode project when it writes CapApp-SPM/Package.swift, and the plugin needs 17.0.

  2. Add the camera usage string to ios/App/App/Info.plist. Word it for your users:

    <key>NSCameraUsageDescription</key>
<string>The camera is used to recognise your face and check that you are present.</string>

  3. Build once in Xcode. Swift Package Manager fetches YEOFR 0.11.2 from GitHub; no login is needed.

Capacitor 7 on CocoaPods

The plugin's podspec compiles the same Swift sources. The engine itself is a binary Swift package and cannot be a pod dependency, so the app adds it directly:

  1. In Xcode, add the package https://github.com/yeo-messaging/YEOFR-SPM at exact version 0.11.2 to the App target.
  2. Set the iOS deployment target to 17.0 in both the Xcode project and the platform :ios line of the Podfile.
  3. On Xcode 27, raise the Capacitor pods' deployment target in a post_install block, as the Capacitor 7 template's Podfile shows for older targets.
  4. Add the camera usage string as above, then npx cap sync and build the workspace.

Android

Android needs three changes, once per app. Capacitor 7 projects also need their template raised, because the engine depends on androidx.core 1.17: Android Gradle Plugin 8.9.1 or newer in android/build.gradle, and compileSdkVersion 36 and minSdkVersion 24 in android/variables.gradle (the template has 8.7.2, 35 and 23). Capacitor 8 projects already meet all three.

1. The YEO repository. The Android engine is in a private Maven repository. Gradle resolves an app's dependencies against the app's own repositories, so your app must declare it, even though the plugin declares it too. Add this to android/build.gradle (the root project):

def yeoSetting = { String property, String variable ->
    providers.gradleProperty(property).orElse(providers.environmentVariable(variable)).getOrElse("")
}

allprojects {
    repositories {
        google()
        mavenCentral()
        maven {
            name = "YEO"
            url = uri(yeoSetting("yeoRepositoryUrl", "YEO_REPOSITORY_URL"))
            credentials {
                username = yeoSetting("yeoUser", "YEO_USER")
                password = yeoSetting("yeoPassword", "YEO_PASSWORD")
            }
        }
    }
}

This is the same block the plugin applies to its own modules from android/gradle/yeo-repository.gradle.kts in the package, written for a Groovy build file.

Put the URL and login YEO gave you in ~/.gradle/gradle.properties on each developer machine:

yeoRepositoryUrl=<the repository URL YEO gave you>
yeoUser=<your user>
yeoPassword=<your password>

On CI, set YEO_REPOSITORY_URL, YEO_USER and YEO_PASSWORD as secret environment variables instead. Never commit any of them. The build stops with a message naming these settings when the URL is missing.

2. Include the plugin's core module. The plugin has two Android modules: a thin Capacitor adapter, which npx cap sync adds for you, and a core module, which it does not. Add these two lines to android/settings.gradle, before apply from: 'capacitor.settings.gradle':

include ':yeofr-core'
project(':yeofr-core').projectDir = new File('../node_modules/@yeomessagingcom/capacitor-yeofr/android/core')

The path is relative to the android/ folder. These lines go away in a later release, when the core is published as a Maven artifact.

3. JDK 21. Capacitor 8 compiles its Android runtime for Java 21. Either run Gradle with a JDK 21, or let Gradle provision one: copy android/gradle/gradle-daemon-jvm.properties from the package into your app's android/gradle/ folder, and add the Foojay resolver at the top of android/settings.gradle:

plugins {
    id "org.gradle.toolchains.foojay-resolver-convention" version "1.0.0"
}

Gradle then downloads a JDK 21 into ~/.gradle/jdks on the first build. Any JDK 17 or later can start the wrapper.

The camera permission is already declared in the plugin's manifest. start() asks the user for it when it has not been decided yet.

Make the page transparent

The preview is a native view behind the WebView. Anything on the page with a solid background covers it. While the camera runs, the plugin makes the WebView itself transparent; your page must be transparent too.

Make the page transparent only while the face page is showing, so the rest of your app keeps its theme. Add this to your global styles (src/global.scss or src/styles.scss):

body.yeofr-camera {
  --ion-background-color: transparent;
  background: transparent;

  ion-app {
    background: transparent;
  }
}

The face page adds the yeofr-camera class to <body> when it enters and removes it when it leaves (see The page). Give your overlays a translucent background, not a solid one. On stop() the plugin puts the WebView's own background back.

Ionic Angular quick start

The code below is a standalone Angular page with signals, split into three parts:

  • FaceTransport: a small interface over the plugin. The service depends only on it.
  • FaceService: owns the session and turns events into signals and plain words.
  • FacePage: starts the camera when the page enters and stops it when the page leaves.

The code below is written for Angular 22 and Ionic 9. On Angular 18 with Ionic 8, add standalone: true to each component decorator and import the Ionic components from @ionic/angular/standalone instead of @ionic/angular; nothing else changes.

The split keeps the plugin at one edge. Unit tests inject a fake transport, and another shell (Cordova, a native host) supplies its own transport while the service and the page stay the same.

The files go in src/app/face/.

1. The transport

face-transport.ts:

import { InjectionToken } from '@angular/core';
import type {
  ActivateOptions,
  EnrolOptions,
  StartOptions,
  YeofrEventMap,
  YeofrEventName,
} from '@yeomessagingcom/capacitor-yeofr';

export type Unsubscribe = () => Promise<void>;

export interface FaceTransport {
  activate(options: ActivateOptions): Promise<void>;
  start(options?: StartOptions): Promise<void>;
  stop(): Promise<void>;
  enrol(options: EnrolOptions): Promise<void>;
  clearTracker(): Promise<void>;
  isEnrolled(): Promise<boolean>;
  on<E extends YeofrEventName>(
    event: E,
    listener: (event: YeofrEventMap[E]) => void,
  ): Promise<Unsubscribe>;
}

export const FACE_TRANSPORT = new InjectionToken<FaceTransport>('FACE_TRANSPORT');

The types come from the plugin with import type, so this file has no runtime dependency on Capacitor.

2. The Capacitor transport

capacitor-face-transport.ts:

import { Injectable } from '@angular/core';
import type { PluginListenerHandle } from '@capacitor/core';
import {
  Yeofr,
  type ActivateOptions,
  type EnrolOptions,
  type StartOptions,
  type YeofrEventMap,
  type YeofrEventName,
} from '@yeomessagingcom/capacitor-yeofr';

import type { FaceTransport, Unsubscribe } from './face-transport';

@Injectable()
export class CapacitorFaceTransport implements FaceTransport {
  activate(options: ActivateOptions): Promise<void> {
    return Yeofr.activate(options);
  }

  start(options?: StartOptions): Promise<void> {
    return Yeofr.start(options);
  }

  stop(): Promise<void> {
    return Yeofr.stop();
  }

  enrol(options: EnrolOptions): Promise<void> {
    return Yeofr.enrol(options);
  }

  clearTracker(): Promise<void> {
    return Yeofr.clearTracker();
  }

  async isEnrolled(): Promise<boolean> {
    const { tracker } = await Yeofr.getTrackerData();
    return tracker !== '';
  }

  async on<E extends YeofrEventName>(
    event: E,
    listener: (event: YeofrEventMap[E]) => void,
  ): Promise<Unsubscribe> {
    const handle: PluginListenerHandle = await Yeofr.addListener(event, listener);
    return () => handle.remove();
  }
}

4. The service

face.service.ts:

import { computed, inject, Injectable, InjectionToken, signal } from '@angular/core';
import type {
  ActivateOptions,
  CameraFailure,
  EnrolPose,
  EnrolProgressEvent,
  FaceFraming,
  ResultEvent,
  YeofrErrorCode,
  YeofrErrorEvent,
} from '@yeomessagingcom/capacitor-yeofr';

import { FACE_TRANSPORT } from './face-transport';

export type CredentialsLoader = () => Promise<ActivateOptions>;
export type SessionState = 'idle' | 'starting' | 'running';
export type FaceProblem = YeofrErrorCode | CameraFailure | 'unexpected';

export const FACE_CREDENTIALS = new InjectionToken<CredentialsLoader>('FACE_CREDENTIALS');

const ENROL_POSES: EnrolPose[] = ['front', 'yawLeft', 'yawRight', 'pitchUp', 'pitchDown'];
const LIVENESS_GRACE_MS = 2000;
const ERROR_CODES: ReadonlySet<string> = new Set<YeofrErrorCode>([
  'badInput',
  'activationFailed',
  'notActivated',
  'unavailableOnSimulator',
  'permissionDenied',
  'cameraFailed',
  'alreadyRunning',
  'notRunning',
  'enrolFailed',
  'storageFailed',
]);

@Injectable({ providedIn: 'root' })
export class FaceService {
  private readonly transport = inject(FACE_TRANSPORT);
  private readonly loadCredentials = inject(FACE_CREDENTIALS);

  private readonly sessionState = signal<SessionState>('idle');
  private readonly resultState = signal<ResultEvent | null>(null);
  private readonly enrolmentState = signal<EnrolProgressEvent | null>(null);
  private readonly enrolledState = signal<boolean>(false);
  private readonly problemState = signal<FaceProblem | null>(null);
  private readonly notLiveForMs = signal<number>(0);

  private activation: Promise<boolean> | null = null;
  private attempt = 0;
  private notLiveSince: number | null = null;

  readonly session = this.sessionState.asReadonly();
  readonly result = this.resultState.asReadonly();
  readonly enrolment = this.enrolmentState.asReadonly();
  readonly enrolled = this.enrolledState.asReadonly();
  readonly problem = this.problemState.asReadonly();

  readonly trusted = computed<boolean>(() => this.resultState()?.status === 'trusted');

  readonly prompt = computed<string>(() => {
    const step = this.enrolmentState();
    if (step !== null) return posePrompt(step.pose);
    if (this.sessionState() === 'idle') return 'Camera is off';
    const result = this.resultState();
    if (result === null) return 'Starting the camera';
    return statusPrompt(result, this.enrolledState(), this.notLiveForMs());
  });

  readonly enrolFraction = computed<number>(() => {
    const step = this.enrolmentState();
    return step !== null && step.posesPlanned > 0 ? step.posesAccepted / step.posesPlanned : 0;
  });

  readonly problemText = computed<string | null>(() => {
    const problem = this.problemState();
    return problem === null ? null : problemPrompt(problem);
  });

  async start(): Promise<void> {
    if (this.sessionState() !== 'idle') return;
    const attempt = ++this.attempt;
    this.sessionState.set('starting');
    this.problemState.set(null);

    const ready = await this.activate();
    if (attempt !== this.attempt) return;
    if (!ready) {
      this.sessionState.set('idle');
      return;
    }

    try {
      await this.transport.start();
      if (attempt === this.attempt) this.sessionState.set('running');
    } catch (error: unknown) {
      // A stop() overtook this start; the plugin rejected it with notRunning.
      if (attempt !== this.attempt) return;
      this.sessionState.set('idle');
      this.problemState.set(problemOf(error));
    }
  }

  async stop(): Promise<void> {
    this.attempt += 1;
    this.sessionState.set('idle');
    this.resultState.set(null);
    this.enrolmentState.set(null);
    await this.transport.stop();
  }

  async enrol(name: string): Promise<void> {
    this.problemState.set(null);
    try {
      await this.transport.enrol({ name, poses: ENROL_POSES });
    } catch (error: unknown) {
      this.problemState.set(problemOf(error));
    }
  }

  async forget(): Promise<void> {
    try {
      await this.transport.clearTracker();
      this.enrolledState.set(false);
    } catch (error: unknown) {
      this.problemState.set(problemOf(error));
    }
  }

  private activate(): Promise<boolean> {
    this.activation ??= this.runActivation();
    return this.activation;
  }

  private async runActivation(): Promise<boolean> {
    try {
      await Promise.all([
        this.transport.on('result', (event: ResultEvent) => this.onResult(event)),
        this.transport.on('enrolProgress', (event: EnrolProgressEvent) => this.onEnrolProgress(event)),
        this.transport.on('registered', () => this.onRegistered()),
        this.transport.on('error', (event: YeofrErrorEvent) => this.onError(event)),
      ]);
      await this.transport.activate(await this.loadCredentials());
      this.enrolledState.set(await this.transport.isEnrolled());
      return true;
    } catch (error: unknown) {
      this.problemState.set(problemOf(error));
      return false;
    }
  }

  private onResult(event: ResultEvent): void {
    const now = performance.now();
    if (event.status === 'notTrusted' && event.matchedName !== null && !event.isLive) {
      this.notLiveSince ??= now;
      this.notLiveForMs.set(now - this.notLiveSince);
    } else {
      this.notLiveSince = null;
      this.notLiveForMs.set(0);
    }
    this.resultState.set(event);
  }

  private onEnrolProgress(event: EnrolProgressEvent): void {
    this.enrolmentState.set(event.phase === 'capturing' ? event : null);
  }

  private onRegistered(): void {
    this.enrolledState.set(true);
    this.enrolmentState.set(null);
  }

  private onError(event: YeofrErrorEvent): void {
    this.problemState.set(event.failure);
    if (event.failure === 'enrolFailed') this.enrolmentState.set(null);
    if (event.failure === 'bindFailed') {
      this.sessionState.set('idle');
      this.resultState.set(null);
    }
  }
}

function statusPrompt(result: ResultEvent, enrolled: boolean, notLiveForMs: number): string {
  switch (result.status) {
    case 'noFace':
      return 'Show your face';
    case 'badFraming':
      return framingPrompt(result.framing);
    case 'notTrusted':
      if (result.matchedName !== null && !result.isLive) {
        return notLiveForMs < LIVENESS_GRACE_MS ? 'Hold still and look at the camera' : 'Not a live face';
      }
      return enrolled ? 'Not recognised' : 'Face found';
    case 'trusted':
      return 'Verified';
  }
}

function framingPrompt(framing: FaceFraming): string {
  switch (framing) {
    case 'tooFar':
      return 'Move closer';
    case 'tooClose':
      return 'Move back';
    case 'multipleFaces':
      return 'One face at a time';
    default:
      return 'Adjust your position';
  }
}

function posePrompt(pose: EnrolPose): string {
  switch (pose) {
    case 'front':
      return 'Face the camera';
    case 'yawLeft':
      return 'Turn your head a little to the left';
    case 'yawRight':
      return 'Turn your head a little to the right';
    case 'pitchUp':
      return 'Tilt your head up a little';
    case 'pitchDown':
      return 'Tilt your head down a little';
  }
}

function problemPrompt(problem: FaceProblem): string {
  switch (problem) {
    case 'permissionDenied':
      return 'Allow camera access for this app in Settings, then try again.';
    case 'cameraFailed':
    case 'bindFailed':
      return 'The camera could not start. Close other apps that use the camera and try again.';
    case 'enrolFailed':
      return 'Enrolment was interrupted. Keep one face in view and try again.';
    case 'storageFailed':
      return 'Your face could not be saved. Try again.';
    case 'badInput':
    case 'activationFailed':
    case 'notActivated':
      return 'Face check is not available in this version of the app.';
    case 'unexpected':
      return 'Face check is not available on this device.';
    default:
      return 'Face check stopped. Try again.';
  }
}

function isErrorCode(value: unknown): value is YeofrErrorCode {
  return typeof value === 'string' && ERROR_CODES.has(value);
}

function problemOf(error: unknown): FaceProblem {
  const code: unknown = typeof error === 'object' && error !== null && 'code' in error ? error.code : undefined;
  return isErrorCode(code) ? code : 'unexpected';
}

What it does:

  • Activates once, lazily. The first start() registers the listeners, loads the credentials and calls activate(). Later calls reuse that result.
  • Guards the session. start() does nothing while a session is starting or running, so the plugin never sees two starts. A stop() during a start() wins: the plugin rejects the pending start() with notRunning, and the service drops it silently.
  • Keeps the listeners. No event arrives after stop(), so the listeners stay registered for the life of the app.
  • Keeps per-frame work small. result arrives for every analysed frame, many times a second. The handler only sets signals; Angular re-renders only what changed. If you log or send analytics, sample them.

5. The page

face.page.ts:

import { DOCUMENT } from '@angular/common';
import { ChangeDetectionStrategy, Component, inject, input } from '@angular/core';
import {
  IonButton,
  IonContent,
  IonFooter,
  IonProgressBar,
  IonToolbar,
  type ViewDidEnter,
  type ViewWillLeave,
} from '@ionic/angular';

import { FaceService } from './face.service';

const CAMERA_CLASS = 'yeofr-camera';

@Component({
  selector: 'app-face-page',
  changeDetection: ChangeDetectionStrategy.OnPush,
  imports: [IonContent, IonFooter, IonToolbar, IonButton, IonProgressBar],
  templateUrl: './face.page.html',
  styleUrl: './face.page.scss',
})
export class FacePage implements ViewDidEnter, ViewWillLeave {
  readonly customerId = input.required<string>();

  protected readonly face = inject(FaceService);
  private readonly body: HTMLElement = inject(DOCUMENT).body;

  ionViewDidEnter(): void {
    this.body.classList.add(CAMERA_CLASS);
    void this.face.start();
  }

  ionViewWillLeave(): void {
    void this.face.stop();
    this.body.classList.remove(CAMERA_CLASS);
  }

  protected enrol(): Promise<void> {
    return this.face.enrol(this.customerId());
  }
}

Notes on the page:

  • Start on enter, stop on leave. ionViewDidEnter runs after the page's enter animation, so the camera does not show behind a page that is still sliding in. ionViewWillLeave stops it before the next page animates in.
  • These Ionic hooks fire only for pages inside <ion-router-outlet>. A page that is not routed through it uses ngOnInit and ngOnDestroy instead.
  • Enrolment and recognition share one page here to keep the sample short. In your app they will usually be separate screens using the same service.

On Android, pick a phone from the list. On iOS, select your team in Xcode and run on an iPhone. Open /face/<an id>, allow the camera, tap Enrol my face, follow the prompts, and the prompt changes to Verified.

What the statuses mean

Each result event carries one fused decision in status. It is the same four values on both platforms. Act on trusted only; the other fields explain it.

status Meaning What to show
noFace No face in view. "Show your face"
badFraming A face is in view but cannot be used: too far, too close, more than one face, or badly placed. The framing hint: tooFar "Move closer", tooClose "Move back", multipleFaces "One face at a time", otherwise "Adjust your position".
notTrusted A usable face that is not the enrolled person, or is the enrolled person but has not passed liveness. See below.
trusted The enrolled person, live. On iPhones with a TrueDepth camera, depth is part of the decision too. Your success state.

notTrusted covers three situations. Tell them apart like this:

Situation How to tell What to show
Recognised, not live yet matchedName is set and isLive is false "Hold still and look at the camera". Liveness takes a moment after a face appears. If it lasts more than about 2 seconds, "Not a live face".
Someone else matchedName is null and someone is enrolled "Not recognised"
Nobody enrolled yet matchedName is null and nobody is enrolled "Face found", and offer enrolment

The other fields:

Field Use
matchedName The enrolled identity the engine recognised, or null.
isLive The liveness decision for this frame, made natively. trusted already includes it.
framing A hint for the user. It is never part of the decision. iOS can report badFraming with framing: 'valid'; show a general hint then.
faceState, detectedCount How many faces the engine sees.
confidence Android only (null on iOS). For display and debugging. Never decide liveness from it.
depthIsThreeD iOS only. The TrueDepth result; null on Android and on iPhones without the sensor.

Do not build your own rule from these fields. trusted is the rule.

When a call fails

Calls reject with a code:

code When What to show
badInput activate() got no credential the platform can use, or a malformed one. enrol() got a blank name. A generic "not available" message. Log the code.
activationFailed The engine refused the credential. The message carries the reason (for example expired). A generic "not available" message. Log the code and message.
notActivated A call that needs the engine ran before activate() resolved. Fix the call order.
permissionDenied The user refused the camera. Ask them to allow the camera in Settings.
cameraFailed The camera could not be started. The message names the reason. "The camera could not start".
alreadyRunning start() while a session runs. Nothing; see Troubleshooting.
notRunning enrol() without a running camera, or a start() that a stop() overtook. Nothing.
storageFailed clearTracker() could not remove the stored face. "Try again".

Never show message to the user. It is native detail for your logs.

Error events

After start() has resolved, failures arrive as error events with a failure value:

failure Platform When
enrolFailed iOS An enrolment capture failed, or the app went to the background during it.
bindFailed iOS The camera did not come back when the app returned to the foreground. The session is stopped.
storageFailed Android A capture completed, but the face could not be saved. It follows registered.

A camera that cannot be started during start() rejects that call with cameraFailed and sends no error event.

Enrolment and the pose walk

Enrolment stores one person's face on the phone, under a name you choose. Call enrol() while the camera runs:

await Yeofr.enrol({ name: customerId, poses: ['front', 'yawLeft', 'yawRight', 'pitchUp', 'pitchDown'] });

Or arm it with the start, which is the same as calling enrol() right after start() resolves:

await Yeofr.start({ enrolName: customerId, poses: ['front', 'yawLeft', 'yawRight'] });

The pose walk. poses is the list of head positions to prompt for, in order. Omit it for a single front capture. More poses put more angles in the gallery, which helps recognition when the head moves. Neither platform can measure head pose, so the prompts guide the user; they do not gate the capture.

  • Android spreads the capture evenly across the poses.
  • iOS runs one capture per pose, with a short pause before each so the user can move.

Progress. While a capture runs, every analysed frame sends enrolProgress:

Field Use
phase capturing, then completed (followed by registered) or failed (followed by an error with enrolFailed).
pose What the user should be doing now. Your app owns the wording.
posesAccepted, posesPlanned Progress through the walk, for a progress bar.
isTargetMatched This frame passed the capture checks (framing and liveness). Show "Hold that pose".

When registered arrives, the face is stored and the next result events can be trusted.

One identity at a time. A capture replaces the enrolled identity. If a capture is cut short, by stop(), a new enrol(), the app going to the background, or a page reload, the previous enrolment is put back as it was. Nothing half-enrolled stays recognisable.

Backgrounding. On iOS, sending the app to the background ends a running capture (enrolProgress failed, then error enrolFailed); start it again when the user returns. On Android the capture stays armed and carries on when the camera resumes.

Storage. The plugin stores the enrolled face template in the app's private storage and keeps it out of device backups. It is restored by activate() the next time the app runs. clearTracker() removes it. If your security policy requires you to hold the template yourself (for example encrypted in your own store), read it with getTrackerData() and restore it with loadTracker() before start().

Licence handling

The engine needs a credential before it does anything. There are two kinds:

Credential What it is Platforms
Licence file A signed .yeolicense file issued for your iOS bundle id. Pass its bytes as base64 in licence. iOS only
Pilot code A time-limited code issued by YEO. Pass it as pilotCode. Android (the only credential); iOS fallback

Pass both in one call. Each platform takes the one it uses: iOS uses the licence when one is given, and Android ignores the licence.

await Yeofr.activate({ licence: licenceBase64, pilotCode });

Use a licence file on iOS. A licence the engine refuses rejects activate() with activationFailed and the reason (expired, bundleIDMismatch, and so on). Your app stays up and can show a message.

An invalid or expired pilot code closes the app on iOS. The engine ends the process during activate(). The promise does not reject, so try/catch does not help. To your users it looks like a crash when the face screen opens. If your iOS app closes at that moment, check the pilot code first, and ship iOS builds with a licence file.

On Android, a pilot code the engine refuses rejects with activationFailed. A licence alone, or no credential at all, rejects with badInput.

Pilot codes expire. Do not hard-code one in shipped source: load it from build configuration or from your backend, so a new code does not need a new binary. Ask YEO for a code that covers your whole test period, and check it on both platforms. Licence files and pilot codes come from YEO support.

App shielding and hardening products

Apps in regulated sectors often ship wrapped in an app shielding or hardening product: runtime protection, anti-tamper, anti-debugging, screen-capture blocking. The plugin needs nothing special from these products, but they change the app the camera runs in. Plan your testing around that:

  • Develop and measure on unshielded builds. Shielding blocks debuggers and log access and can change timing, so problems are hard to see and numbers are hard to compare.
  • Run acceptance on a shielded build, on real phones. Use a shielded build of the same commit, on iPhones and Android phones, before every release. Check activation, camera start, a full enrolment, recognition, leaving and re-entering the face page, and sending the app to the background and back.
  • Expect black screenshots. On a shielded build, screenshots and screen recordings of the face page usually come out black. That is the screen-capture protection working, not a camera fault. If you need a recording, film the phone with a second device.
  • Compare before you escalate. If something works unshielded and fails shielded, note the error codes from both builds of the same commit and send both to your shielding vendor and to YEO.

Symptom Cause and fix
Could not find com.yeomessaging:yeofr-android:0.2.29 The YEO repository is missing from your root android/build.gradle. Add the block from Android.
capacitor-yeofr: the YEO engine repository URL is not set Set yeoRepositoryUrl, yeoUser and yeoPassword in ~/.gradle/gradle.properties, or YEO_REPOSITORY_URL, YEO_USER and YEO_PASSWORD in the environment.
401 or Unauthorized from the YEO repository The URL is set but the login is missing or wrong.
Could not find com.youreyeonly:yeofr-core The two :yeofr-core lines are missing from android/settings.gradle, or the path in them is wrong.
A Gradle error about Java 21 Capacitor 8 needs JDK 21. Install it, or let Gradle provision it (step 3 under Android).
iOS: Swift Package Manager reports a minimum platform version conflict Set the App target's deployment target to 17.0, then npx cap sync.
iOS on CocoaPods: the plugin is not in the build npx cap sync has not run since the install, so the Podfile does not list the plugin yet, or the YEOFR-SPM package is missing from the Xcode project. Run npx cap sync and follow Capacitor 7 on CocoaPods.
iOS app closes when the face page opens An invalid or expired pilot code (see Licence handling), or NSCameraUsageDescription is missing from Info.plist. iOS ends any app that opens the camera without it.
Android phone: the camera shows but results stay noFace Check that Google Play services is installed and up to date. Phones without Google Play services are not supported.
start() rejects permissionDenied The user refused the camera. iOS asks only once; after that the user must allow it in Settings. Android stops asking if the user chose not to be asked again. checkPermissions() tells you the state before you start.
Simulator or emulator: results stay noFace Expected. Neither gives the engine a real face. Test on phones.
alreadyRunning start() ran while a session was running. There is one camera session per app: two pages each starting the camera, or a start without a stop. Keep the session in one service, as FaceService does. On iOS, activate() and loadTracker() also reject alreadyRunning while a session runs.
The camera stops after a page reload or live reload By design. Loading a page stops the native session, so no camera runs behind a page that no longer knows about it, and the old JavaScript listeners are gone. The new page starts the camera again when it enters. Router navigation inside the app does not reload the page; your leave hook stops the camera.
The camera runs but the screen is white or your theme colour Something opaque covers the preview: the yeofr-camera class is not on <body>, or an element has a solid background.
The preview is sideways The preview does not follow rotation in this release. Lock the face page or the app to portrait.
Every call rejects UNAVAILABLE in the browser There is no web engine. Run on a phone.
registered never arrives The capture only counts frames that pass framing and liveness. Fill the frame, hold still, use good light.
